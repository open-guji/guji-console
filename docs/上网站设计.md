## 一、一句话方案

**在 `console.kaiyuanguji.com` 上跑一份控制台**：前后端由同一个进程出，放在那台搁置中的美国服务器上，Caddy 做 HTTPS；登录走网站已有的 OAuth（`client_id=collate`），去掉现在的 Basic Auth 共享密码；**会员登录后能看、能裁，裁的就是正式人裁事件**；服务器上的数据从中心库拉、产物由出产物的机器打包送过去，服务器不跑管线；`guji-console` 仓打 tag 直接发到服务器，和网站仓的发布互不牵连。

## 三、整体形态

```
  会员 / 校对者浏览器
        │  https://console.kaiyuanguji.com
        ▼
  Caddy（TLS、限流、/healthz）
        │  127.0.0.1:8640
        ▼
  guji-console 进程（FastAPI，同时出前端静态文件）
   ├─ 读：工作区 products/ cache/ 原图 + 数据目录（中心库的本机副本）
   ├─ 写：人裁事件（谁裁的记 email）
   └─ 定时：guji db sync（人裁回中心库）、guji snap import（收产物）
        │
        ▼
  中心库  ←→  本地各机（A21–A24、A30 照常整理）
```

前后端同源：会话靠 cookie，不用开 CORS、不用跨站 cookie；前端本来就打进包里由 FastAPI 出。一个进程、一条发布线，和主站完全分开。

## 四、网址与入口

- 子域 `console.kaiyuanguji.com`（Sheldon 10-29 定），DNS 一条 A 记录指服务器。
- 主站导航加一个「校对平台」链接；没登录访问控制台自动跳网站登录，回来落到原页面。

## 五、权限

| 能力 | 会员 member | 校对者 reviewer | 管理员 admin |
|---|---|---|---|
| 看册、看页、叠图、字形库、Step9 阅读 | ✓ | ✓ | ✓ |
| **在审卡上裁决（直接落人裁事件）** | ✓ | ✓ | ✓ |
| 消费事件、金标、评测、台账、下单跑任务 | — | — | ✓ |
| 跑管线 | 服务器上一律关掉 | | |

- 裁决不分身份，都是人裁。事件里 `reviewer` 记登录的 email，以后要按人看质量、按人撤回都查得到。
- 会员能看哪些册：只开「上架」的册（第六节），不是服务器上所有工作区。

**实现**：`_ROLE_TIER` 加 `member`，会员和校对者在裁决路由上同级；管理类路由仍要 admin；每个路由逐个标级，没标的默认拒绝，加一条测试扫全部路由。服务器上禁止 `--no-auth`（host 不是 127.0.0.1 又带 `--no-auth` 就拒绝启动）。

**不动契约、不动指纹**：用的是现有事件格式，不加字段。

## 六、服务器上的数据

| 东西 | 从哪来 | 怎么更新 |
|---|---|---|
| 册配置、人裁、台账、字形库 | 中心库 | `guji db sync --watch 600`（systemd 定时） |
| 原图 | guji-workspace 或 R2 页表 | 上架时拉一次 |
| 产物 products/、字块 cache/ | 出产物的机器 `guji snap pack` | 服务器 `guji snap import` 定时收 |

- **服务器不跑管线**：2 核跑整册太慢，也会和本地整理的人跑出两份产物。产物由 A21–A24、A30 跑完按钉的版本打包送上去。
- **上架清单**：服务器上一份 `published.yaml`（哪些册对会员开放），admin 在控制台里改。
- 页头显示这页产物的版本和送达时间。产物过期（本地已重跑、新的还没送到）的页标「待更新」，不收裁决，免得裁到旧产物上。
- 人裁回中心库后，`sync` 顺带落库（`glyphdb_admit`、`glyph_audit`）照常跑，和本地人裁一样。

## 七、部署流程（和主站分开，不设 staging）

1. `guji-console` 仓 PR 投 `main`，CI 跑测试和前端构建。
2. 打 `vX.Y.Z` tag → GitHub Actions：构建前端、打 wheel → 推到服务器专用 venv → `systemctl restart` → 冒烟（`/healthz`、`/api/version`、登录跳转）。冒烟不过自动装回上一个 wheel。
3. 服务器上 cv 钉一个发布版本（不跟 dev），升级 cv 单独一次。
4. 凭据（OAuth client secret、id_token 密钥、会话密钥、中心库令牌、部署 SSH 密钥）只放服务器环境文件和仓库 secrets，不进 git。
5. `/healthz` 接 open-guji-monitor。

## 八、安全与负载

- 管理类接口要 admin；没标级的路由默认拒绝。

- 角色每小时回网站刷新一次（已有），网站撤了会员资格最晚一小时后失效。
